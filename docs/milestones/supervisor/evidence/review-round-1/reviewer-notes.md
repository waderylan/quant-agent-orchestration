# Blind review round 1

- This set contains 48 sealed questions: 16 portfolio-manager, 16 equity-researcher and 16 self-directed-investor cases.
- Design inputs are only this worktree's `AGENTS.md` and `PRODUCT_BRIEF.md`. No implementation, existing tests, answers, history, account state or provider evidence was inspected. No product execution or external requests occurred.
- Expected evidence describes provenance, accounting/period compatibility, calculation lineage and truthful handling of uncertainty. It is not a factual financial-answer key. Fiscal endpoints repeated in R1-022 come directly from the supplied brief. All numeric financial scenario assumptions are explicitly hypothetical.
- The harness can supply controlled original-filing excerpts, exact financial observations and market responses without live provider access. Synthetic observations must be visibly identified as fixture data; a synthetic value must never be asserted as a factual company result.
- Conditions override ordinary source availability for a case. A nominally supported company/year may have an unavailable source in that controlled test. No-entitlement and external-display restrictions are explicit fixture metadata rather than guesses about a provider's real contract.
- Live-quote freshness is judged relative to the controlled request clock, observation timestamp, timezone and session metadata. The `years` selection scopes historical research; it does not assert that the market observation occurred in that fiscal year. Quote-only and hypothetical cases retain one allowed year as selection metadata.
- Quarterly cases retain the relevant annual baseline in the two-year selection where needed. Year-to-date cash-flow durations must remain distinct from standalone quarters. No missing quarterly category disclosure is inferred merely from a missing fixture response.
- Risk fixtures permit full-section absence claims only when the relevant original sections are actually available. Partial retrieval permits qualified conclusions, never definitive removal. Ordinary complete cases may correctly conclude no material change if the provided evidence supports that result.
- R1-014 requires a real cancellation lifecycle signal; merely adding the word cancel to a user prompt does not exercise cancellation. Request cancellation is assumed externally observable even if no final answer is emitted. Its acceptable-outcome labels describe any retained report, not permission to continue generating after cancellation.
- R1-013 requires genuinely overlapping independent requests with distinguishable source identifiers and interleaved returns. The companion NVIDIA request is fixture setup, not cross-turn context or an additional unlisted question.
- R1-016 intentionally exceeds company/year coverage. R1-032 intentionally requests unsupported AMD FY2026 historical evidence. R1-031 intentionally leaves selection empty to test essential ambiguity.
- `completed` means the requested supported evidence and conclusions are supplied. `partial` preserves useful verified findings while naming missing or unsupported components. `needs_clarification` identifies essential unresolved user choices. `coverage_gap` identifies evidence unavailable for the request. The evaluator should apply failure criteria alongside these labels rather than score a label alone.
- R1-004, R1-009 through R1-016, R1-021, R1-024, R1-025, R1-027, R1-029, R1-031, R1-032 and R1-035 through R1-047 provide adversarial, incompatible-basis, ambiguity, unsupported-scope or controlled failure conditions. Several normal cases combine financial, risk and market evidence to expose handoff loss.
- The set is sealed before parent application execution. Do not alter cases after observing implementation behavior. Hashes reported to the parent identify the sealed files; this note intentionally does not embed its own hash.
